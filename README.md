# چت ناشناس↑cₕₐₜ — نسخه‌ی Async (Balethon + SQLite)

این پروژه، بازنویسیِ کامل سورس اصلیِ شما (که سینک بود، با `requests` و
polling دستی، و داده‌ها را در یک فایل JSON نگه می‌داشت) به یک ساختار:

- **کاملاً async** با کتابخونه‌ی **[Balethon](https://balethon.ir)** (مخصوص بله)
- **دیتابیس SQLite سریع** (با `aiosqlite`، WAL mode، ایندکس روی فیلدهای پرکاربرد)

به‌جای یک فایل تک‌غول‌پیکر، کد به ماژول‌های منطقی تقسیم شده تا نگه‌داری و
توسعه‌ی بعدی راحت‌تر باشد.

## ساختار پروژه

├── utils.py                  ← توابع کمکیِ خالص (haversine، safe_int، ...)
├── database.py                ← لایه‌ی دیتابیس (aiosqlite) — همه‌ی CRUD اینجاست
├── bot_instance.py            ← نمونه‌ی Client بله‌تون + state موقتیِ بازی‌ها/صف‌ها
├── keyboards.py               ← سازنده‌های کیبورد (Reply/Inline)
├── filters.py                 ← کاندیشن‌های سفارشی (state کاربر، ادمین، چت فعال و...)
├── force_join.py              ← بررسی/مدیریت جوین اجباری
├── profile_common.py          ← نمایش پروفایل من/دیگران (مشترک بین چند هندلر)
├── lists.py                    ← لیست مخاطبین/لایک‌ها/بلاک‌شده‌ها
├── background.py               ← تسک‌های دوره‌ای (تایم‌اوت matchmaking و سنگ‌کاغذقیچی)
├── handlers/                    ← همه‌ی هندلرهای ربات، هرکدام در فایل خودش
│   ├── __init__.py                 (⚠️ ترتیب importها مهم است؛ توضیح داخل فایل)
│   ├── gate.py                      بن/جوین‌اجباری (همیشه اول)
│   ├── chat.py                      چت خصوصی، پیام دایرکت، رله، هدیه

│   ├── registration.py              ثبت‌نام + /start + لینک‌های دعوت/ناشناس/بازی

│   ├── dooz.py                      بازی دوز

│   ├── misc.py                      راهنما/قوانین
│   ├── export.py                    خروجی پروفایل (JSON/TXT/HTML)
│   └── fallback.py                  فال‌بک «بازگشت 🔙» (همیشه آخر)

│   └── smoke_test.py            تست end-to-end بدون نیاز به شبکه/توکن واقعی

## نصب و راه‌اندازی

```bash
cd balechat
python3 -m venv venv && source venv/bin/activate     # اختیاری ولی توصیه‌شده
pip install -r requirements.txt
```

سپس توکن و آیدی ادمین را یا با Environment Variable بدهید:

```bash
export BALE_BOT_TOKEN="توکن-ربات-شما"
export ADMIN_ID="آیدی-عددی-ادمین"
python3 main.py
```

یا مستقیم در `config.py` ادیت کنید (مقدار پیش‌فرض همان مقدار سورس اصلی است،
حتماً قبل از ران واقعی عوضش کنید).

### فایل‌های اختیاری (عکس‌ها)
این‌ها در سورس اصلی هم اختیاری بودن (اگه نباشن، fallback متنی می‌فرسته):
- `Aksss.jpg` (کنار main.py) → عکس پیش‌فرض پروفایل
- `IMG.jpg` (کنار main.py) → بنر دعوت دوستان
- `images/dooz.jpg` → عکس لینک بازی دوز

### دیتابیس
با اولین اجرا، فایل `bot.sqlite3` کنار main.py ساخته می‌شود (مسیرش با
`BOT_DB_PATH` قابل تغییره). دیگه به `uyser_data.json` نیازی نیست.

## تست (بدون نیاز به توکن/شبکه‌ی واقعی)

```bash
python3 tests/smoke_test.py
```

این اسکریپت یک کلاینت فیک می‌سازد و جریان‌های اصلی (ثبت‌نام → پروفایل →
matchmaking → چت → هدیه → قطع چت → دوز → جستجو) را end-to-end تست می‌کند.

## چه چیزهایی عیناً پورت شده؟

تقریباً همه‌ی فیچرهای سورس اصلی:
ثبت‌نام، پروفایل (نمایش/ادیت/GPS)، جستجوی ساده و پیشرفته، افراد نزدیک،
matchmaking (شانسی/جنسیت/اطراف)، چت خصوصی + پیام دایرکت + درخواست چت +
هدیه‌ی سکه + رله‌ی پیام، دعوت دوستان + لینک پیام ناشناس، خرید سکه (کارت‌به‌کارت
+ تایید ادمین با OCR بهترین‌تلاش)، بازی دوز و سنگ‌کاغذقیچی (شانسی/لینک/داخل
چت)، پنل مدیریت کامل (ارسال همگانی، انتقال سکه، سکه همگانی، جوین اجباری،
بلاک/آنبلاک، آمار، لیست پرداخت‌ها)، لایک/بلاک/مخاطبین/گزارش/سایلنت/
اطلاع‌رسانیِ پایان چت، و خروجی پروفایل (JSON/TXT/HTML).

## چند تفاوت/ساده‌سازی نسبت به سورس اصلی (مهم بدونید)

1. **صف‌های matchmaking و سشن‌های دوز/سنگ‌کاغذقیچی در RAM هستند، نه دیتابیس**
   (دقیقاً مثل سشن‌های دوز/سنگ‌کاغذقیچی در نسخه‌ی اصلی که هم در حافظه بودن).
   یعنی با ری‌استارت ربات، صف‌ها و بازی‌های نیمه‌کاره از بین می‌روند. اگه
   نیاز به دوام کامل دارید (مثلاً چند پروسس/کریون)، باید این بخش‌ها را هم
   به Redis یا جدول دیتابیس منتقل کنید.
2. **رسیدِ پرداخت در حین چتِ فعال**: در سورس اصلی، حتی اگر کاربر هم‌زمان در
   یک چت فعال بود، عکسِ رسید پرداخت پردازش می‌شد. در این بازنویسی، برای
   سادگی، اگر کاربر هم‌زمان هم منتظرِ ارسال رسید باشد و هم در یک چت فعال،
   عکس به‌جای پردازش‌شدن به‌عنوان رسید، به مخاطبِ چت رله می‌شود (یک حالتِ
   گوشه‌ایِ نادر). برای رفع کامل، کافیه هندلر `buy_state_is("awaiting_receipt")`
   را به ابتدای `handlers/__init__.py` (قبل از `chat`) منتقل کنید.
3. **رفع یک باگِ نسخه‌ی اصلی**: تایید/ردِ پرداخت توسط ادمین، روی پیامی که
   با عکس فرستاده شده بود از `editMessageText` استفاده می‌کرد (که برای
   پیام‌های عکس‌دار درست کار نمی‌کند)؛ اینجا با `edit_message_caption`
   درست شده.
4. **خروجی HTML/JSON/TXT** عیناً پورت شده ولی برای ساخت فایل از `tempfile`
   استفاده می‌کند (مثل قبل).

## نکته‌ی مهم درباره‌ی ترتیب هندلرها

بله‌تون هندلرها را به ترتیبِ ثبت‌شدن (=ترتیب importها) چک می‌کند و اولین
هندلری که شرطش برقرار باشد اجرا می‌شود. این دقیقاً معادل زنجیره‌ی
`if/elif/continue` در حلقه‌ی پولینگِ نسخه‌ی اصلی است. توضیح کامل ترتیب و
چرایی‌اش بالای `handlers/__init__.py` نوشته شده — اگر هندلر جدیدی اضافه
می‌کنید، حتماً اول آن کامنت را بخونید تا جای درستش رو پیدا کنید (مثلاً
هرچی که باید حتی وقتیِ کاربر در چتِ فعاله هم کار کنه، باید قبل از
`handlers/chat.py` ایمپورت بشه).

## مجوزها / دیتابیس فعلی شما

فایل `uyser_data.json` قبلی‌تان دیگر استفاده نمی‌شود؛ اگر کاربرهای موجود را
می‌خواهید منتقل کنید، یک اسکریپتِ migration ساده لازم دارید که هر کلید این
JSON را با `await database.save_user(uid, user_dict)` ذخیره کند (ساختار
دیکشنریِ کاربر تقریباً عیناً همان ساختار قبلی است، پس migration ساده خواهد بود).
